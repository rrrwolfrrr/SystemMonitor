# Сборка SystemMonitor

## Структура проекта

```
SystemMonitor/
├── main.py              # Точка входа с системным треем
├── server_core.py       # Ядро сервера Flask + WebSocket
├── config.py            # Конфигурация
├── libre_monitor.py     # Работа с LibreHardwareMonitor DLL
├── cache.py             # Кеширование данных
├── utils.py             # Вспомогательные функции
├── routes.py            # Маршруты Flask
├── fps_monitor.py       # Отслеживание одного процесса через PresentMon/ETW
├── templates/           # HTML шаблоны
├── static/              # Статические файлы (CSS, JS)
├── build.spec           # Конфигурация PyInstaller
├── build.bat            # Скрипт сборки (Windows)
├── installer.iss        # Скрипт Inno Setup
├── icon.ico             # Иконка приложения
├── create_icon.py       # Скрипт для генерации иконки
├── third_party/PawnIO/  # Исходники PawnIO/PawnPP и лицензии
├── env.env              # Конфигурационный файл окружения
└── *.cs                 # Исходники C#-адаптеров
```

Правила `.gitignore` позволяют добавить DLL-зависимости, версии которых
соответствуют ссылкам в LibreHardwareMonitor v0.9.6, и отдельный PresentMon с
MIT-лицензией; исходный код PawnIO v2.1.0, закреплённая версия PawnPP и тексты
лицензий включены в `third_party/PawnIO/2.1.0`. Официальный
`PawnIO_setup.exe` v2.1.0 включён в приватный репозиторий с разрешения автора;
подробности и область разрешения указаны в
[THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md). Не переносите файл в публичный
репозиторий и не распространяйте его отдельно от этого проекта без
подтверждения, что разрешение автора распространяется и на такие случаи.
`LhmVisitorAdapter.dll` создаётся локально из C# исходника скриптом сборки.

## Автоматическая проверка проекта

После изменений запускайте:

```cmd
autotest.bat
```

Команда выполняет unit-тесты, проверку матрицы оборудования, JSON-схемы
сенсоров, HTTP-маршрутов и отсутствие фоновых потоков при импорте.
Для проверки фактических датчиков текущего компьютера используйте:

```cmd
autotest.bat --live
```

Случаи матрицы, которых нет на текущем компьютере, помечаются как `skipped`.
После сборки дополнительно проверьте дистрибутив:

```cmd
autotest.bat --build dist\SystemMonitor
```

## 1. Требования

### Python пакеты
```bash
pip install flask flask-cors psutil wmi pywin32 websockets pystray Pillow qrcode python-dotenv pyinstaller pywebview
```

Встроенное окно Dashboard использует WebView2 Runtime. Если Runtime недоступен,
SystemMonitor сообщит об ошибке и предложит открыть Dashboard в браузере.
Во встроенном окне Dashboard заполняет доступную область и подстраивает карточки
при изменении размера окна, размещая их ровными рядами с промежутками; обычный
браузерный вариант сохраняет собственную настройку размера и положения Dashboard.
Во встроенной теме «Терминал (CMD)» вместо карточек отображаются выбранные датчики.
Тему можно выбрать в меню «Темы», а набор датчиков и их порядок настроить кнопкой
«Датчики терминала»; настройки сохраняются в профиле Dashboard.
Поддерживаются внутренние вкладки Dashboard: у каждой вкладки отдельные карточки,
макет, настройки и тема. Источники компьютеров добавляются через «Источники ПК»;
каждую стандартную или пользовательскую карточку можно привязать к выбранному
источнику. Пользовательские карточки позволяют собрать произвольный набор
датчиков, в том числе с разных компьютеров. Вкладки и список источников хранятся
в localStorage профиля WebView2 или браузера.
Для удалённого источника запустите SystemMonitor на другом ПК, укажите его частный
IPv4-адрес и порт (по умолчанию 5000) и разрешите этот порт в брандмауэре Windows
для частной сети. Подключение работает без токенов и предназначено только для
доверенной локальной сети; сервер разрешает проксирование только фиксированного
маршрута `/stats` к IPv4-адресам RFC1918.
Открыть мобильный Dashboard на телефоне можно кнопкой «QR для телефона» в панели
Dashboard: отсканируйте код камерой, подключив телефон к той же Wi-Fi/локальной
сети. При необходимости разрешите SystemMonitor в брандмауэре Windows для
частной сети.
### FPS без внутриигрового оверлея

SystemMonitor отслеживает один процесс за раз через PresentMon 2.6.0 и Windows ETW;
код в игру не внедряется и оверлей не создаётся. По умолчанию выбирается процесс
активного окна компьютера, на котором запущен сервер. В Dashboard и мобильном
Dashboard можно переключиться на ручной выбор процесса или вернуться к активному
окну. Доступны текущий FPS, средний FPS за последние 30 секунд, 1% low и время
кадра. Пока кадры не обнаружены или приложение простаивает, значения показываются
прочерками, а не нулём.
Для текущей частоты используется `FrameTime` приложения, а не только длительность
показа кадра (`DisplayedTime`): это не ограничивает результат частотой монитора,
когда игра рендерит быстрее неё. Программа не устанавливает верхний предел FPS;
фактическое число зависит от игры, её настроек, GPU и режима отображения.
Краткие задержки передачи данных до 3 секунд не сбрасывают текущее показание.

В установочной сборке PresentMon поставляется рядом с приложением, включая его
лицензию в `PRESENTMON_LICENSE.txt`. FPS поступает в `/stats` отдельно от
аппаратных датчиков и доступен подключённым клиентам по локальной сети. Точность
зависит от игры, графического API и режима отображения; некоторые приложения или
драйверы могут не предоставлять полные данные. Если процесс не определяется
автоматически, обновите список и выберите его вручную.
При запуске приложение останавливает оставшиеся ETW-сессии SystemMonitor только
для уже завершившихся процессов; предупреждения самого PresentMon записываются
в журнал приложения.

### Карточка батареи ноутбука

В полном и мобильном Dashboard батарея отображается как обычная карточка,
которую можно включать и отключать в настройках видимых карточек. При наличии
данных показываются заряд, состояние питания, оставшееся/расчётное время,
проектная и фактическая ёмкость, оценка здоровья аккумулятора, напряжение,
химический состав и другие доступные параметры WMI. Набор значений зависит
от модели батареи и драйвера; отсутствующие системой параметры не подменяются
расчётными значениями. Для статуса и заряда также используется psutil как
резервный источник.
Как и остальные API SystemMonitor без токенов, список процессов и выбор цели
доступны внутри доверенной локальной сети; не публикуйте порт сервера в Интернет.

### Память GPU

Карточка GPU отдельно показывает выделенную видеопамять и общую память,
используя формат «занято / доступно». Занятое выделенное/общее значение
считывается из Windows-счётчиков GPU Adapter Memory; лимит общей памяти
рассчитывается как половина установленной физической памяти Windows. Общий
объём выделенной памяти берётся из основного GPU-провайдера (LibreHardwareMonitor
или включённого NVIDIA-провайдера). Если конкретный источник не предоставляет
значение, вместо него выводится прочерк. На системах с несколькими GPU данные
занятой памяти берутся с адаптера с наибольшим текущим использованием выделенной
памяти.

Историю температуры можно открыть кнопкой «История ПК», выбрать компьютер и
период до 30 дней; удалённые данные запрашиваются с его собственного хранилища
истории. В настройках температурных порогов задаются отдельные значения CPU/GPU
для каждого источника; GPU предупреждает также по температуре Hotspot. Фильтр
«Только CPU»/«Только GPU» доступен при выборе датчиков в пользовательских
карточках и при добавлении датчиков в стандартные карточки.
Кнопки «Экспорт всех вкладок» и «Импорт всех вкладок» переносят архив с вкладками,
их макетами и источниками, а также пользовательскими темами, пресетами и порогами
температур. При импорте содержимое этих настроек заменяется данными архива.

### Мобильный Dashboard

Страница `/mobile` по умолчанию адаптируется к ширине смартфонов и планшетов:
на узких экранах карточки идут одной колонкой, на планшетах — двумя, на широких
экранах — тремя; при желании можно принудительно выбрать одну колонку. В мобильной
версии можно закреплять показатели в кратком обзоре, выбирать дополнительные
датчики для карточек, переименовывать и упорядочивать их, сворачивать карточки,
а также просматривать графики температуры по сохранённой истории. Есть локальные
профили настроек и варианты оформления; пользовательский CSS можно загрузить в
настройках. Частота обновления начинается с одной секунды. Настройки мобильного
интерфейса и профили хранятся в localStorage браузера отдельно от настроек
десктопного Dashboard.
Дополнительно доступна компактная тема «CMD (Windows 11)» без карточек: выводит
выбранные датчики в моноширинном терминальном интерфейсе, позволяет найти их и
зафиксировать порядок строк; настройки этой темы сохраняются в профиле мобильного
Dashboard.

## 2. Сборка .exe через PyInstaller

### Вариант A: Автоматическая сборка
Запустите `build.bat`:
```cmd
build.bat
```

Этот скрипт:
1. Выбирает Python из локального `.venv`/`venv` (если он есть), затем проверяет Python и PyInstaller
2. Очищает старые файлы сборки
3. Собирает .exe через PyInstaller
4. Проверяет комплектность дистрибутива и совпадение встроенного Dashboard с текущим `templates\dashboard.html`

Скрипт собирает исходники из своей папки и создаёт
`dist\SystemMonitor\SystemMonitor.exe`. Он **не устанавливает и не обновляет**
уже установленное приложение и не пересобирает Setup-файл. Для проверки новой
версии запускайте EXE из `dist\SystemMonitor`; для распространения через Setup
отдельно соберите установщик по инструкции ниже.

### Вариант B: Ручная сборка

```cmd
# Установить зависимости
python -m pip install -r requirements.txt pyinstaller

# Очистить старые файлы
rmdir /s /q build 2>nul
rmdir /s /q dist 2>nul

# Собрать .exe
python -m PyInstaller build.spec --clean --noconfirm
```

Результат будет в `dist\SystemMonitor\SystemMonitor.exe`

## 3. Сборка установщика через Inno Setup

`build.bat` собирает PyInstaller-дистрибутив, но не запускает Inno Setup.
Установщик собирается отдельной командой после успешной сборки программы.

### Ручная сборка

1. Убедитесь, что `SystemMonitor.exe` собран (лежит в `dist\SystemMonitor\SystemMonitor.exe`)
2. Запустите Inno Setup Compiler:
```cmd
iscc installer.iss
```

Результат: `installer_output\SystemMonitor_Setup_2.0.1.exe`.

Установщик работает в контексте текущего пользователя, чтобы его записи в
`HKCU` и автозапуск относились к нужной учётной записи. При обновлении или
удалении запущенный SystemMonitor закрывается; если для закрытия требуется
повышение прав, Windows запросит подтверждение UAC. Сам SystemMonitor всё равно
запускается с правами администратора для доступа к датчикам. Установка PawnIO
и настройка правил брандмауэра также могут отдельно запросить UAC.
Перед установкой проверяется версия .NET Framework по значению `Release`
(минимум 528040, то есть .NET Framework 4.8); установщик рассчитан на x64.
Автозапуск регистрируется как задание Планировщика Windows «при входе в
систему» с наивысшими правами, поскольку исполняемый файл требует повышения
прав. Это позволяет запускать его без запроса UAC при каждом входе. Для
создания задания подтверждается UAC; включить или выключить его позже можно
через меню значка SystemMonitor в системном трее. Старые записи автозапуска из
`HKCU\...\Run` распознаются и удаляются при переключении настройки.

## 4. Настройка build.spec

Ключевые параметры в `build.spec`:

- **`console=False`** — без консольного окна (для трей-приложения)
- **`uac_admin=True`** — требует права администратора (нужно для чтения датчиков)
- **`icon='icon.ico'`** — иконка приложения
- **`hiddenimports`** — скрытые импорты для PyInstaller
- **`datas`** — дополнительные файлы (шаблоны, иконки, конфиги)
- **`binaries`** — DLL файлы LibreHardwareMonitor
- **`LhmVisitorAdapter.dll`** — нативный .NET-адаптер официального `IVisitor`;
  автоматически пересобирается `build.bat` перед PyInstaller
- **`PawnIO_setup.exe`** — официальный установщик PawnIO для CPU/MSR/EC-сенсоров
- **NVAPI/AMD ADL/ACPI-EC** — необязательные интерфейсы видеодрайверов и прошивки.
  SystemMonitor обнаруживает их автоматически, но не устанавливает и не заменяет
  драйверы производителя.

## 7. Устранение неполадок

### Ошибка: "LibreHardwareMonitorLib.dll не найден"
- Убедитесь, что DLL файлы включены в `build.spec` (проверьте секцию `binaries`)
- Убедитесь, что DLL файлы лежат в той же папке, что и .exe

### Не отображаются температура, напряжение или мощность CPU

Проверьте в `/api/diagnostics` или в логе поле `pawnio`. Должны быть:
`installed=true` и `running=true`. Если PawnIO отсутствует, повторно запустите
`PawnIO_setup.exe` от имени администратора из папки установки и перезапустите
SystemMonitor. Официальный LibreHardwareMonitor использует этот же драйвер.

### Ошибка: "pystray не установлен"
- Добавьте в `build.spec`:
```python
hiddenimports = [
    ...
    'pystray',
    'pystray._win32',
]
```

### Ошибка: "PIL не найден"
- Добавьте в `build.spec`:
```python
pil_datas, pil_binaries, pil_hiddenimports = collect_all('PIL')
hiddenimports += pil_hiddenimports
datas += pil_datas
```
- Удалите `PIL` из `excludes`

### Приложение не запускается после сборки
- Проверьте, что `console=False` в `build.spec` (для трей-приложения)
- Запустите из командной строки, чтобы увидеть ошибки:
```cmd
SystemMonitor.exe --noconsole
```

### Иконка не отображается в трее
- Убедитесь, что `icon.ico` включён в `datas` в `build.spec`
- Функция создания иконки в `main.py` должна возвращать валидное изображение PIL

## Запуск

1. Скопируйте все .dll файлы в папку с SystemMonitor.exe
2. Запустите SystemMonitor.exe

При первом запуске будет создан файл env.env с настройками по умолчанию.

## Примечания

- Файл SystemMonitor.exe включает в себя все зависимости и статические файлы
- DLL файлы LibreHardwareMonitor должны находиться в той же папке, что и .exe файл
- При сборке с `--windowed` окно консоли не будет отображаться (логи пишутся в server.log)
- Для отладки можно убрать `--windowed` и использовать `--console`

## Current Windows build

The supported path is the repository root's `build.bat`. It runs
`python -m PyInstaller build.spec --clean --noconfirm`, creates a one-directory
`dist\SystemMonitor\` distribution, and then runs `verify_build.py` to check
the executable, LHM DLL, templates, and PyInstaller `_internal` directory.

`installer.iss` consumes that exact `dist\SystemMonitor\` directory. Build the
distribution first, then open the script with Inno Setup (or run
`iscc installer.iss`). No C# SDK is required: `update_visitor.py` uses
PythonNet when available and falls back to recursive `Update()`; `UpdateVisitor.cs`
is only an optional reference implementation.

DLL hashes and best-effort file versions are exposed by
`/api/diagnostics/snapshot`. Keep the generated `dist\` and `build\` folders
out of source control.
