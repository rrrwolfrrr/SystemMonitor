# Правила публикации SystemMonitor на GitHub

Этот документ определяет, какие файлы разрешено отправлять в репозиторий и какие должны оставаться только на этом компьютере. Если назначение файла неясно, не публикуйте его, пока владелец проекта явно не одобрит это.

## Разрешено публиковать

Публикуйте только необходимые для проекта файлы из следующих категорий:

- исходный код приложения и тесты: отслеживаемые Git файлы `*.py`, `*.cs`, `*.js`;
- интерфейс и веб-ресурсы проекта: отслеживаемые файлы в `templates/`, `static/` и `assets/`;
- документация проекта, инструкции сборки, лицензии и уведомления об open-source компонентах: например, `README.md`, `BUILD.md`, `LICENSE`, `THIRD_PARTY_NOTICES.md`, `PRESENTMON_LICENSE.txt` и материалы в `Документация проекта/`;
- тестовые матрицы и примеры конфигурации без секретов: например, `hardware_test_matrix.json`, `manifest.json`, `templates/*.json` и `.env.example`;
- поддерживаемые сценарии сборки и запуска проекта: например, `autotest.bat`, `build.bat`, `build_installer.bat`, `update_and_build.bat`, `start_server.bat`, `templates/build_dashboard.bat`, `build.spec` и `installer.iss`;
- исходный код, лицензии и notices в `third_party/`, если они нужны проекту и их лицензии позволяют распространение;
- уже одобренные и отслеживаемые Git зависимости, необходимые для сборки/запуска: текущие allowlist DLL в `.gitignore`, `PresentMon-2.6.0-x64.exe` и иные бинарные файлы только после отдельной проверки происхождения, версии и лицензии.

Наличие подходящего расширения само по себе не разрешает публикацию. Новый файл должен соответствовать категории выше и быть явно проверен перед добавлением в коммит.

## Никогда не публиковать

- `AI_MEMORY.md` и любые файлы памяти/заметок ассистента, содержащие личный или рабочий контекст.
- `.copilot-backups/`, любые резервные копии файлов, снимки рабочей папки и временные копии.
- `.env`, `.env.*` с локальными настройками, токенами или паролями, приватные ключи, сертификаты и файлы учётных данных. Исключение `.env.example` разрешено только с фиктивными значениями и без секретов.
- локальные настройки, содержащие адреса, имена пользователей, пути, сетевую топологию, идентификаторы устройств или другие данные конкретного компьютера; логи, дампы, диагностические снимки и личные данные.
- локальные скрипты синхронизации: `sync_main.bat`, `sync_main.ps1`, `git pull --ff-only origin main.ps1` и любые аналогичные временные скрипты, не утверждённые как часть продукта.
- локальный установщик `PawnIO_setup.exe`, если он отдельно не прошёл проверку происхождения и лицензии; не публиковать его только потому, что он находится в корне проекта.
- сгенерированные каталоги `build/`, `dist/`, `installer_output/`, `__pycache__/`, `.venv/`, `venv/`, runtime-кэш, базы данных, журналы и выходные файлы тестов.
- неизвестные или неотслеживаемые бинарные файлы, резервные сборки, временные экспорты и файлы, не прошедшие проверку происхождения, лицензии и необходимости.

`env.env` уже отслеживается в репозитории и предназначен для безопасных значений по умолчанию. Не добавляйте в него локальные переопределения, пароли, токены или персональные данные; сначала проверьте каждое изменение этого файла.

## Обязательная проверка перед публикацией

1. Добавляйте файлы в коммит только явными путями (`git add <файл>`); не используйте `git add -A` или `git add .`.
2. Проверьте staged-список (`git diff --cached --name-status`) и содержимое (`git diff --cached`). В нём должны быть только нужные разрешённые файлы.
3. Убедитесь, что в staged-списке нет запрещённых файлов, секретов, локальных данных, резервных копий и неутверждённых бинарников.
4. Если файл не классифицирован или его безопасное содержимое нельзя подтвердить, не публикуйте его и запросите решение владельца проекта.

Этот документ описывает политику, а не заменяет проверку каждого коммита. Сам документ можно публиковать как документацию проекта; его создание не означает автоматическое добавление в коммит или отправку на GitHub.
